2. Data on the user’s device

The browser’s local storage, mainly IndexedDB, holds tasks, habits, goals, schedules, notes and reflections, workout journal, sleep, recovery, breathing, meditation, measurements, profile fields, and preferences. localStorage also contains service settings, analytics-session state, retry queue, and the local backup key.

3. Specific backend data

  • Account: Telegram ID, name, username, XP, level, and creation date.
  • Notifications: Telegram ID, habit or workout notification text, time, cron expression, status, and creation date.
  • Premium: Telegram ID, status, validation flag, end date, and creation date.
  • Product and bot analytics: Telegram ID, event type, page, target, duration, metadata, and time. Mini App metadata may contain language, platform, app and Telegram versions, time zone, and session ID; bot events may contain language code, username, and first name.
  • Payments and revenue: payment ID, Telegram ID, plan, amount, status, dates, currency, and payment method.
  • Referrals: referrer and referred Telegram IDs and date.
  • Backup: Telegram ID, device ID, ciphertext backup, client update time, and server update time.
  • Numeric feature records: Telegram ID, JSON numeric mental-function results, and update time.
  • Terms and deletion: Telegram ID, document type and version, acceptance date and method, 18+ confirmation, request ID, and deletion-request state and dates.
  • AI cache and usage: Telegram ID, section, language, numeric-snapshot fingerprint, result, provider, creation and expiry dates, request day, generation count, and last-generation time.

4. Encrypted backup

If backup is used, the app encrypts selected data on the device before upload. Task, habit, workout-journal, sleep, recovery, breathing, and note content reaches the UltyMyLife database as ciphertext. UltyMyLife does not store the decryption key in its database. The key stays on the device and in Telegram CloudStorage. Full compromise of the device or Telegram account may expose the key.

5. Groq AI analysis

UltyMyLife uses Groq, LLC (United States), not Grok/xAI. Immediately before the request, the backend creates a strict allowlisted payload. Groq receives only de-identified numeric aggregates: product section, response language, period length in days, numeric metrics, comparisons, and data-quality flags. It does not receive Telegram ID, username, name, internal ID, exact dates, fingerprint, backup, keys, task or habit names and descriptions, exercise names, notes, reflections, or other user-written text. User-created names, descriptions, and notes are not sent to Groq. The limited request is processed outside Russia. Groq retention is controlled by Groq rules, not UltyMyLife code.

6. Data the service does not request

UltyMyLife is a self-organization and lifestyle/wellness product, not a medical service. It does not request diagnoses, treatment information, medicines, or medical documents. Do not enter such information into free-text fields. Weight, sleep, workouts, breathing, stress, and productivity indicators are not automatically classified as medical data.

9. Data retention periods

  • A deletion request blocks access immediately and can be cancelled for 7 calendar days. The account, notifications, backup, mental records, analytics, AI cache and usage, Premium, and referrals are then deleted.
  • By default, AI cache remains effective for 24 hours. Server setting INSIGHT_CACHE_HOURS can change this duration.
  • Expired AI-cache rows are not automatically deleted. They remain until the same row is overwritten or the account is deleted.
  • Analytics events have no separate automatic retention period in code and remain until account deletion.
  • AI usage, notifications, backup, mental records, and Premium have no separate automatic cleanup period; they are deleted with the account or are replaced or deleted earlier by the feature.
  • Payments and revenue remain after deletion with Telegram ID removed. Code defines no separate retention period.
  • Terms acceptance and deletion records remain without Telegram ID but with its HMAC hash. Code defines no separate retention period.
  • UltyMyLife code does not define retention for console or hosting logs.
